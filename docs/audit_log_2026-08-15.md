## 1. Executive summary

The product is a **.NET 8 WPF + ASP.NET Core + WebRTC DataChannel** remote-support prototype. Signaling, accept/reject, and JPEG frame transfer over SIPSorcery now exist, but the app is **not production-ready**.

Core user complaints are **confirmed in code**, not just UX:

1. **Remember me does not restore username/password or auto-login.** Tokens may be written, but `TryAutoLogin` is never called and password is never stored.
2. **Forgot password is a dead button** (no `Command`).
3. **Fullscreen is an empty stub.**
4. **Mouse/keyboard cannot work reliably:** `CoordinateMapper` is injected twice (session vs capture), so capture almost always sees `IsConfigured == false`. Mouse-move floods the same DataChannel as video.
5. **Screen is slow by design:** GDI full-screen capture, JPEG re-encode every frame, no dirty-rects, no DXGI, quality hardcoded (1280px / Q40 / 15 FPS), UI thread `Dispatcher.Invoke` per frame, no adaptive bitrate, no TURN.

Security is **below remote-access bar**: hardcoded JWT secret and admin password, anonymous customer session APIs, no login lockout, HTTP, SIPSorcery GHSA, SignalR detailed errors always on.

Recommendation: treat current tree as **Phase-0 prototype**. Do not put it on the public internet until Phase 0–1 in section 8 are done.

## 2. Confirmed user-reported defects (root cause)

### U1 — Support login: username/password not remembered

**Files:** `src/SupportAgent/ViewModels/LoginViewModel.cs`, `src/SupportAgent/Views/LoginWindow.xaml`, `LoginWindow.xaml.cs`, `Services/Implementation/TokenStorage.cs`

Evidence:

- Checkbox `RememberMe` defaults to `true`.
- On success it only calls `_tokenStorage.SaveTokens(...)` (JWT access + refresh), **not** username or password.
- `PasswordBox` is unbound; there is no DPAPI store for credentials.
- `TryAutoLogin` exists but **`LoginWindow.OnLoaded` never calls it**. Startup always shows empty login.
- Even if auto-login ran, session would lack `Username` / `Role` / `UserId` unless `/auth/me` is called (it is not wired).

User expectation (“مرا به خاطر بسپار” fills user+password) ≠ implementation (silent JWT file). Result: **every launch requires typing credentials**.

### U2 — Forgot password is useless

**File:** `LoginWindow.xaml` lines 124–125

```xml
<Button Content="{Binding LoginForgotPassword}" Style="{StaticResource TextLink}"
        HorizontalAlignment="Right" VerticalAlignment="Center"/>
```

No `Command`, no click handler, no API (`AuthController` has login/refresh/logout/me only). Server has no email/reset flow.

**Recommendation:** remove the control until a real reset exists. A dead link looks like a broken product.

### U3 — Fullscreen does nothing

**File:** `SessionViewModel.cs`

```csharp
[RelayCommand] private void ToggleFullscreen() { }
```

String resources exist (`Session_Fullscreen`) but toolbar does not even bind this command in `SessionView.xaml`. No `WindowStyle` / `WindowState` / exclusive viewer window.

### U4 — Mouse and keyboard do not work

Several independent bugs stack:

| # | Defect | Evidence |
|---|---|---|
| 1 | **Two `CoordinateMapper` instances** | `App.xaml.cs`: `AddTransient<CoordinateMapper>()`, `AddTransient<WpfMouseCapture>()`, `AddTransient<RemoteDesktopSession>()`. Session updates mapper A on frames; capture reads mapper B → `IsConfigured` stays false → all mouse handlers return immediately. |
| 2 | Mouse gated on `IsConfigured` | `WpfMouseCapture` OnMouseMove/Down/Up/Wheel all bail if mapper not configured. |
| 3 | Display size may be 0 | Mapper uses `_captureElement.RenderSize` before layout → even a shared mapper can stay unconfigured. |
| 4 | Keyboard needs Image focus | Keys are on `PreviewKeyDown` of the `Image`. No global hook; Image must be focused (only on mouse-down). |
| 5 | Coordinate space mismatch | Capture scaled to max 1280; injection uses `GetSystemMetrics(SM_CXSCREEN)` physical pixels. If remote is 1920 and stream is 1280, clicks land wrong **even after mapper is fixed**. |
| 6 | DPI / virtual desktop | No `MOUSEEVENTF_VIRTUALDESK`, no DPI awareness. Multi-monitor / 125–150% scaling will miss. |
| 7 | Mouse-move flood | Every WPF `MouseMove` is a DataChannel message competing with JPEG frames. |
| 8 | Consent / injection | Injection no-ops if `WindowsInputInjection.IsEnabled` is false. Default UI is AllowRemoteControl=true, but ControlMessage can revoke; failed SendInput is swallowed. |
| 9 | Classic `SendInput` packing | `INPUT` + `INPUTUNION` explicit layout is a known 32/64-bit footgun (project is x64; still fragile vs `MOUSEINPUT` extra fields). |

### U5 — Image is very slow (will be worse on the internet)

Pipeline today:

1. `GdiScreenCapture`: `CopyFromScreen` / BitBlt of **full monitor**, then scale to ≤1280, JPEG Q=**40**.
2. `ScreenStreamingManager` at **15 FPS**; `quality: 60` argument is **ignored** because format is already JPEG.
3. Each frame wrapped in `ScreenFrameTransport` + `TransportEnvelope` (JSON headers + copy).
4. Sent on **one unreliable-sized SCTP message** sharing the channel with input/clipboard/files.
5. Support: deserialize + `Dispatcher.Invoke` + `BitmapImage` decode **on UI thread** every frame.
6. No dirty-region, no DXGI Desktop Duplication, no H.264, no hardware encode, no frame skip when send queue is backed up (except drop on exception).
7. ICE is **Google STUN only** (`WebRtcConfiguration.Default`). No TURN. LAN may work; **many NATs will fail or hairpin poorly**. Symmetric NAT / CGNAT = no P2P.
8. JPEG still tens of KB per frame. At 15 FPS that is hundreds of kbps–Mbps **before** SCTP overhead. On Wi-Fi/WAN: queueing, stalls, “slideshow”.

There is **no UI** for Low / Balance / High.

### U6 — Product feels incomplete

UI shows Chat, Audio, Mute, Upload, diagnostics FPS/bitrate/latency. Reality:

- Chat: local `ObservableCollection` only; never sent on DataChannel (`SendChatMessage` does not call transport).
- Audio / Mute toggles: no pipeline start; Shared NAudio code is unused by agents.
- FPS/bitrate/latency labels: diagnostics timer does not set `_fps` / `_bitrate` / `_latency` from stream metrics.
- Chat toolbar button has no command.
- Duplicate leftover `ViewModels/SessionViewModel.cs` (excluded in csproj).
- Mixed FA/EN chrome (toolbar still English: Mouse, Keyboard, Chat…).

## 4. Why LAN still feels slow

Even on one PC / one LAN:

1. Software JPEG of ~1–2 megapixels-scaled frames 15 times per second.
2. WPF decode on UI thread.
3. DataChannel + JSON envelopes + copies.
4. GDI capture contention with the desktop being captured (including the customer window).
5. No skip-if-busy: capture waits on encode waits on send.

On the internet add: STUN-only ICE, loss, RTT, SCTP retransmission of large JPEG blobs (head-of-line vs video). **Without TURN + H.264 (or at least aggressive Low preset + congestion), WAN is not viable.**

## 8. Remediation roadmap (ordered, phased)

Do **not** start Phase 2 until Phase 0 input + login + security basics are done. Screen “pretty” without working mouse is the wrong order for a support tool.

### Phase 0 — Stop the bleeding (3–7 days)

Goal: operator can log in once, see a usable picture, move mouse/keyboard, not ship accidental open APIs.

1. **Login Remember me (correct product meaning)**  
   - Persist **username** (DPAPI) + refresh token (already).  
   - Pre-fill username; never store password.  
   - Call refresh + `/auth/me` on startup (`TryAutoLogin` must be invoked from `LoginWindow`).  
   - If user unchecks Remember me, `ClearTokens`.  
2. **Remove Forgot password** from XAML until a real flow exists.  
3. **Fix input DI:** one `CoordinateMapper` per session (register scoped/instance owned by `RemoteDesktopSession`; pass same instance into `WpfMouseCapture`).  
4. **Map coordinates in capture-space** (1280 JPEG size) **or** send original monitor size in frame metadata and map to that consistently with `SendInput` virtual-desktop + DPI.  
5. **Throttle mouse-move** (e.g. 30–50 Hz) and send buttons immediately.  
6. **Focus + keyboard:** capture keys at Window level when “Keyboard” is on; suppress local shortcuts where safe.  
7. **Customer consent:** default explicit; ignore peer `ConsentGranted` unless it matches UI; log injection failures.  
8. **Security hotfixes:** JWT secret from env/user-secrets; change seed admin or force password change; `[Authorize]` customer accept/reject/terminate with device JWT bound to identifier; rate-limit login; disable SignalR detailed errors outside Development.  
9. **Hide** Chat/Audio/Mute if unwired (or disable with tooltip “not available”).

Exit criteria: reconnect after restart without typing password (username filled + auto session); click lands on customer screen; type in Notepad; no anonymous terminate.

### Phase 1 — Screen quality and viewer (1–2 weeks)

Goal: LAN feels like remote support, not a slideshow; operator controls quality; fullscreen works.

1. Quality enum **Low / Balance / High** in Support toolbar; ControlMessage to customer to change capture width/Q/FPS **at runtime**.  
2. Skip frames if last send not completed (back-pressure).  
3. Decode off UI thread (`Freeze` BitmapSource, then `BeginInvoke` assign).  
4. DXGI Desktop Duplication (fallback GDI).  
5. Optional dirty-region or lower FPS when desktop idle (hash/histogram).  
6. **Fullscreen:** dedicated viewer window or `WindowState=Maximized` + hide chrome; Escape to exit; Image Stretch bound to Fit vs Actual.  
7. Diagnostics: real FPS (frames rendered / sec), bitrate (bytes sent * 8 / sec), RTT from existing Ping/Pong.  
8. Binary frame header (not JSON) to cut CPU.

Exit criteria: Balance ≥10 FPS on same-machine LAN; Low usable on a 5 Mbps profile; fullscreen works; quality change visible within 1–2 seconds.

### Phase 2 — Internet and product completeness (2–4 weeks)

1. **TURN** (coturn) + ICE policy; show “Relay/Direct” in UI.  
2. Replace JPEG with **hardware H.264** (or libwebrtc) for High; keep JPEG for Low.  
3. Separate DataChannel (or SCTP stream) for input vs media.  
4. Real chat over `TransportMessageType.Chat` or hide forever.  
5. Audio: wire NAudio **or** remove toggles.  
6. File transfer to disk with size cap, extension allow-list, customer accept path.  
7. HTTPS + certificate story for agents.  
8. Upgrade/replace SIPSorcery per GHSA.  
9. SQLite → PostgreSQL for anything beyond single-box demo.

Exit criteria: two NATed networks with TURN relay; file send 50 MB without RAM spike; chat round-trip; TLS.

### Phase 3 — Production hardening (ongoing)

1. CI (build + tests + vuln scan) on every PR.  
2. E2E: login, code, accept, frame checksum, click inject, quality switch.  
3. Lockout / audit export / 2FA.  
4. Customer agent installer, autostart, unattended vs attended modes.  
5. UAC / Secure Desktop limitations documented; Ctrl+Alt+Del policy.  
6. Localization pass (FA/EN) on all session chrome.  
7. Observability: structured session-id logs, metrics, crash dump.  
8. Remove dead files (`Compile Remove` leftovers).  
9. Penetration test of hubs and customer anonymous surface.  
10. Runbook: rotate JWT, rotate admin, TURN creds, DB backup.
